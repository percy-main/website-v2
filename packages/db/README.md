# @percy-main/db

The database layer: the Kysely client factory, the generated schema type, migrations, and a few domain service helpers. Consumed by `apps/api` (frontends never touch it).

## Layout

- `src/client.ts` — `createClient(...)` returning a typed Kysely client (pg pool). Services take this client as their first parameter; there is no singleton.
- `src/__generated__/db.ts` — the `DB` type, **generated by kysely-codegen**. Do not hand-edit; regenerate after migrations.
- `src/migrations/` — timestamped Kysely migrations (`up`/`down`).
- `src/service/` — thin, typed query helpers for a few domains (charges, memberships, juniors). No ORM; everything is the Kysely query builder.
- `scripts/` — migration/reset tooling backing the root `db:*` scripts.

## Workflow

Run these from the repo root (see the [`add-migration`](../../.claude/skills/add-migration/SKILL.md) skill):

1. `pnpm run db:migration` — scaffold a migration, then write its `up`/`down`.
2. `pnpm run db:up` — apply pending migrations.
3. `pnpm run db:types` — regenerate `__generated__/db.ts` from the live schema.

## Non-obvious notes

- The connection string resolves `DATABASE_MIGRATION_URL` → `DATABASE_URL` → a local default; migrations and codegen use the migration URL.
- Percy Main's RDS rejects non-SSL connections for non-master users — append `?sslmode=require` to any `DATABASE_URL` pointing at it.
- Never `ALTER TABLE` by hand to fix schema drift; fix the root cause (a missing migration or wrong package version) instead.
- Use `sql<string>` for aggregates (`SUM`/`COUNT`/...) — Postgres returns bigint as a string.
